# Домашний сервер: страница и технические письма

Страница статуса остаётся по прежнему адресу Tailscale, порт 8090. Телефон должен быть подключён к Tailscale. Новый APK не требуется.

## Что показывает страница

Питание ноутбука, батарею, температуру, память, диск и связь; отдельные статусы доступности страницы, работы независимого монитора, запуска расписания и завершения проверки роботов. Успех определяется по run-health.json, а не по изменению cron.log. Ошибка чтения состояния не исправляется заменой данных.

Роботы показаны карточками. Диагностика, обслуживание и журналы раскрываются по нажатию. Страница обновляет показатели каждые 30 секунд, сохраняя открытые разделы; поле ключа и действия владельца при этом не сбрасываются.

## Технические письма

Монитор monitor.js работает отдельным процессом, независимо от браузера и расчётов. Проверка каждые 30 секунд. SMTP и получатель берутся из существующего config.json; пароль не выводится. Имя отправителя «Домашний сервер», темы «[Сервер]», содержание не относится к торговой стратегии. Торговые письма сохраняют прежнее оформление.

Переход на батарею, заряд 20%/10%, температура 80/90 °C, критически мало диска, нехватка памяти, повторная потеря интернета/Tailscale, зависший/прерванный ход, ошибки и пропуски запусков вызывают тревоги. Температурные пороги — первоначальные настройки монитора, не характеристика предельно допустимой температуры ноутбука. Их можно уточнить через config.json.monitor. Пороги батареи доступны на странице владельцу.

Письма отправляются при начале события, изменении серьёзности и восстановлении. Для сохраняющейся критической тревоги — напоминание раз в 6 часов. У батареи и температуры есть запас для устранения дребезга порогов. История состояний и очередь сохраняются до отправки; при сбое доставки повтор через увеличивающийся интервал до часа. После принятия письма SMTP-сервером элемент удаляется из очереди. Абсолютная доставка ровно один раз при обрыве связи в момент SMTP-подтверждения не гарантируется.

Очередь и сбой доставки видны на странице. Для теста есть отдельная кнопка с честным тестовым письмом. Полностью выключенный сервер не отправляет сообщения — внешний наблюдатель остаётся отдельной задачей.

## Действия владельца

В раскрываемом блоке «Действия владельца» вводится тот же ключ API, что в приложении. Он хранится только в поле страницы: не записывается в URL, cookie или localStorage. Доступ к POST /api/admin проверяется сервером. Без правильного ключа все действия отклоняются.

Доступны: тестовое письмо, создание и скачивание копии состояния роботов, запись фактического обслуживания, пороги батареи, перезапуск монитора и страницы. Перезапуски требуют подтверждения, торговые процессы не останавливаются.

Для кнопки перезагрузки нужен один административный шаг владельца. На ПК:

```powershell
ssh -t home-server "sudo sh ~/projects/elliott-waves-web/server/enable-reboot.sh"
```

Пароль вводится только в своём терминале. Скрипт через visudo разрешает egor только `/usr/bin/systemctl reboot`, без общего root-доступа. Он НЕ перезагружает сервер. После этого обновить страницу. Реальная перезагрузка произойдёт только после кнопки и подтверждения владельца. При активном ходе действие отклоняется; перед перезагрузкой сохраняется копия и ставится короткая блокировка новых запусков.

## Обслуживание и копии

Учёт начат 03.11.2026. Это не дата замены термопасты; фактические даты неизвестны до записи владельцем. Активные часы учитываются с установки монитора по монотонному времени, отдельно от календарных дней и сна. При перезагрузках счётчик сохраняется.

Раз в месяц монитор напоминает об обзоре состояния, раз в три месяца — об осмотре вентиляции. Термопаста меняется по состоянию, не автоматически по календарю. Даты реальных работ можно сохранить на странице.

Копия vacc.json автоматически создаётся ежедневно в data/backups и по кнопке. Копии не содержат SMTP/API-токенов из config.json, но содержат приватное состояние роботов; скачивание защищено ключом. Автоматического восстановления или удаления старых копий нет.

## Запуск и установка

manage.js ensure запускается cron раз в минуту и при загрузке, проверяет отдельные процессы status.js и monitor.js. Существующая строка run.js каждые 5 минут сохраняется. Если процесс монитора жив, но показатели не обновлялись более 3 минут, супервизор перезапустит его и сохранит техническое событие; повторное вмешательство ограничено одним разом в 10 минут. Monitor использует публичные датчики и пользовательские службы, административные права ему не нужны.

Установка из staging-папки: Node запускает install-monitor.js с явным путём установленной папки server. Проверяется синтаксис, сохраняются старые исходники и crontab в data/code-backups. config.json и состояние роботов не заменяются. maintenance-default.json копируется только при отсутствии data/maintenance.json.

Файлы: data/monitor.json — показатели, тревоги и очередь; run-health.json — последний запуск; maintenance.json — фактические даты; monitor-settings.json — пороги; mail-requests.json — запросы тестовых писем. Всё внутри data игнорируется Git. Монитор пишет только короткие коды ошибок в monitor.log, без секретов.
